What's in the notebook

    -

    Each square is 10 pages, where a page is about 500 words. The model behind this is simplified: about 30 messages a day, a typical long-context model, and no caching for the typical assistant. The real trick is the order of the notebook. The parts that rarely change go first, so the AI reuses them from cache instead of paying to read them again.

    Engineering notes

    Things production taught me

    Short lessons from systems that had to work for real users.

    Fewer agents, better context

    Multi-agent diagrams look impressive and cost you at every hand-off. Collapsing Memorae's pipeline into one harness with good runtime context made it faster and more human at the same time.

    Memorae Autopilot V2 · −70% latency

    Order your prompt for the cache

    Put what never changes first and what changes every turn last. Then the cost of a long-lived user stops growing with their history.

    Runtime context block design

    A claimed action with no tool call is a bug class

    When an agent says "done" without calling a tool, patching one prompt is not enough. I fixed it structurally in the core loop and the prompt layers so the whole class disappears.

    Hallucination audit, Memorae

    Push beats poll

    Gmail polling meant a 15-minute delay before the agent noticed anything. Direct Pub/Sub made it react in seconds, which is the difference between proactive and late.

    Integration layer, Memorae

    Separate finding facts from reasoning about them

    Splitting data gathering from root cause analysis, with a ledger in between, made answers traceable and every claim backed by evidence.

    Insights Agent, Aunix

    Pick models on your own benchmark

    Leaderboards don't know your prompts. I compare cost, quality, latency and context on our real traffic, then migrate carefully, down to tokenizer details.

    Model strategy, Memorae
